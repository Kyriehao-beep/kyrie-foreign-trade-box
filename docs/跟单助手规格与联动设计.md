# 跟单助手（Follow-up Assistant）规格与联动设计

> 面向外贸业务员的小工具：把"谈成的客户"收进一个可跟进的看板，并与「单据制作」双向联动。
> 数据纯浏览器本地（localStorage），零后端、零运维，契合"体量小、不懂技术"的终端用户。

## 1. 它解决什么

外贸业务员常把客户散落在微信 / Excel / 报价单里，谁跟到哪一步全靠脑子记。
跟单助手把"已洽谈 / 已报价 / 已下单 / 出货 / 收款"显式标出来，再叠加**优先级、紧急度、跟进时间线、业务员建议**，
让"谁该跟了、该说什么"一眼可见，而不是让 AI 替你拍板——符合"逐字段标记待核对、用户掌控"的产品方法论。

## 2. 数据模型（src/services/followUpStore.ts）

一条"跟单记录" `FollowUpRecord`：

| 字段 | 说明 |
|---|---|
| `id` | 本地生成的唯一 id |
| `buyer` | 买方信息（复用 `domain/documents` 的 `Party`：公司名/国家/联系人/电话/邮箱） |
| `productSummary` | 产品摘要（如"硅胶徽章 ×500件，热熔胶 ×200套"） |
| `amount` / `currency` | 金额与币种（按"数量×单价"汇总） |
| `incoterm` | 贸易术语（如 FOB 深圳） |
| `stage` | 阶段：`inquiry` 洽谈 / `quoted` 已报价 / `ordered` 已下单 / `shipped` 出货 / `paid` 收款 |
| `priority` | 优先级（重要程度）：`high` 高 / `medium` 中 / `low` 低，对应 红 / 橙 / 绿 |
| `nextFollowUpAt` | 下次跟进日期（`yyyy-mm-dd`），用于自动推算紧急度 |
| `activities` | 跟进时间线 `FollowUpActivity[]`：`{ id, at, kind, text, suggestion? }`，`kind` ∈ note 备注 / contact 联系 / stage 阶段 / system 系统建议 |
| `sourceDocType` / `sourceDocNumber` | 来源单据类型与编号 |
| `notes` | 备注 |
| `createdAt` / `updatedAt` | 时间戳 |

- 存储键：`ktb_followup:v1`（localStorage）
- `upsertFollowUp`：按"买方公司名"自动去重，避免同一客户重复建档；`priority` 缺省 `medium`、`nextFollowUpAt` 缺省空、`activities` 缺省 `[]`
- `upsertFromDraft`（单据一键建档）：默认 `stage: quoted`、`priority: medium`、`nextFollowUpAt = 今天+3天`、并写入一条 `system` 初始活动
- `computeStats`：客户总数、本月新增、进行中（洽谈+已报价）、已成交（已下单+出货+收款）、成交金额、**今日待跟进**（`urgency` 为 overdue/today 的条数）、**已逾期**（overdue 条数）
- `getUrgency(record)`：按 `nextFollowUpAt` 推算 → `overdue` 已逾期 / `today` 今天跟进 / `soon` 即将到期（≤2天）/ `normal` 跟进中 / `none` 未排期
- `logFollowUpActivity(id, activity, nextFollowUpAt?)`：追加一条时间线，可顺带更新下次跟进日期
- `getSuggestion(record)` / `STAGE_PLAYBOOK`：业务员跟进剧本（见 §4）
- `suggestNextDate(days)`：返回 `今天+days` 的 `yyyy-mm-dd`

## 3. 联动（核心，未变）

```
单据制作（谈成客户、做报价单/PI）
   │  「加入跟单助手」──推送──▶  买方信息 + 产品摘要 + 金额 + 贸易术语 + 单据类型/编号
   ▼
跟单助手（客户/交易聚合 + 阶段看板 + 优先级/紧急度 + 跟进时间线）
   │  「新建单据」──回填──▶  自动带出买方信息 + 贸易术语 + 币种，回到单据制作
   ▼
形成闭环：做单即建档，建档即能回做单
```

### 出向：单据 → 跟单助手
- 入口：单据中心右上角「加入跟单助手」按钮（`DocumentWorkspace.addToFollowUp`）
- 读取当前草稿 `draft.buyer / items / trade`，调用 `upsertFromDraft(draft)`
- 阶段默认置为 `quoted`（已做单据 ⇒ 至少已报价）；按公司名去重；写入初始系统活动

### 入向：跟单助手 → 单据
- 入口：跟单卡片「新建单据」按钮 → `navigate('/documents?followup=<id>')`
- `DocumentWorkspace` 挂载时读取 `?followup` 参数，回填 `buyer` + `trade.incoterm` + `trade.currency`
- 回填后清除 URL 参数，避免刷新重复带入

## 4. 优先级 / 紧急度 / 跟进时间线 / 业务员建议

### 4.1 优先级（重要程度，红/橙/绿）
- `high` 高 → 红（`bg-red-*`）；`medium` 中 → 橙（`bg-amber-*`）；`low` 低 → 绿（`bg-emerald-*`）
- 新增/编辑表单用带色点的三按钮选择；卡片左侧显示色点 + 文字标签
- 排序权重：高 > 中 > 低

### 4.2 紧急度（按下次跟进日期自动推算）
- 来自 `nextFollowUpAt`，无需手动维护：逾期(红) > 今天(橙) > 即将到期≤2天(橙) > 跟进中(灰) > 未排期(灰)
- 卡片显示紧急度徽章；统计区给出"今日待跟进 / 已逾期"计数
- 列表默认按 **紧急度 → 优先级 → 更新时间** 排序，谁该跟了一目了然

### 4.3 跟进时间线（后续跟单过程）
- 每条记录可展开"跟进记录"，按时间倒序展示 `activities`
- 支持两类手动记录：**加备注**（note）、**记联系**（contact）
- 例如下完单后，可记录"已同步生产进度，并问客户是否需追加订单/有新项目"——正是用户要的"后续跟单过程"

### 4.4 业务员跟进剧本（按阶段给建议，可一键采纳）
`STAGE_PLAYBOOK` 以专业业务员视角为每阶段预设：阶段目标、建议动作、推荐跟进间隔、可直接复制的**话术模板**：

| 阶段 | 目标 | 建议动作 | 间隔 | 话术要点 |
|---|---|---|---|---|
| 洽谈 | 确认需求、拿反馈 | 主动问是否收到报价、有无疑问 | 3天 | 确认报价收到+可重新核算 |
| 已报价 | 消除顾虑、促单 | 问是否打样/放宽 MOQ/特殊交期 | 4天 | 打样/MOQ/交期可争取 |
| 已下单 | 保交付+挖增量 | **同步生产进度，主动问是否需追加订单、有无新项目** | 7天 | 一起安排省运费更快交期 |
| 出货 | 稳体验+索反馈 | 发提单/跟踪号，收货后问体验 | 5天 | 跟踪号+收货体验+转介绍 |
| 收款 | 催回款+维护复购 | 提醒账期/催尾款，问复购计划 | 14天 | 尾款节点+下批排产 |

- 展开卡片时显示当前阶段剧本：建议动作 + 话术（可复制）
- 「采纳并排期」：一键把 `nextFollowUpAt` 设为 `今天+间隔`，并写入一条 `system` 活动（含话术），便于后续跟踪

## 5. 页面与入口

- 导航：**左侧分组侧栏**（`src/components/Sidebar.tsx`），桌面常驻、移动端汉堡抽屉
  - 分组：工作台(首页) / 业务(外贸单据中心、**跟单助手**) / 工具箱(贸商工具箱) / 账户(会员中心、管理后台)
  - **跟单助手作为「业务」分组的直达项**，不再需要回首页下滑（这是本版要解决的核心痛点）
- 页面：`src/pages/FollowUpPage.tsx`
  - 顶部统计卡片：客户总数 / 进行中 / **今日待跟进** / **已逾期** / 已成交+金额
  - 筛选 chips：全部 / **今日待跟进** / 各阶段
  - 图例：优先级 红/橙/绿 + 紧急度说明（列表默认按紧急度+优先级排序）
  - 客户卡片：阶段徽章、优先级色点、紧急度徽章、下次跟进日期、操作（新建单据 / 推进阶段 / 编辑 / 删除）
  - 卡片可展开"跟进记录"：时间线 + 添加备注/联系 + 业务员建议（采纳并排期/复制话术）
  - 新增/编辑表单（inline 面板）：含优先级三按钮、下次跟进日期选择器
- 路由：`/follow-up`（包 `ProtectedFeature`，与单据/工具箱一致，受 3 天试用门控）

## 6. 范围边界（本版）

- 已含：优先级、紧急度、跟进时间线、业务员建议剧本（话术可复制、可采纳排期）
- 不含：自动提醒推送（浏览器通知）、阶段看板拖拽、多业务员隔离、跨设备同步——均留作后续
- 数据仅存本机：清缓存 / 换设备会丢失（已与用户确认接受，v1 用 localStorage 跑通）
