# 六类外贸单据 A4 PDF 导出设计

日期：2026-08-16  
状态：已获用户口头批准，待用户复核本文档  
适用产品：Kyrie的外贸盒子

## 1. 背景与问题

当前“导出 PDF”直接调用浏览器打印。实际导出的 `testing.pdf` 出现浏览器页眉页脚、网址、错误分页、预览栏被压窄、中文逐字换行和表格重叠。参考文件 `PI-202608-6369.pdf` 使用固定 A4 画布生成，能在单页内稳定呈现品牌抬头、买卖方资料、产品表格、合计与贸易条款。

根因不是单据数据错误，而是响应式网页布局被直接交给浏览器打印。网页中的网格、粘性侧栏、滚动容器和响应式断点并不具备可靠的印刷分页语义。

## 2. 目标

- 六类单据全部使用统一的专业 A4 PDF 导出引擎：报价单、形式发票、销售合同、商业发票、装箱单、报关信息。
- 导出结果不包含浏览器日期、网址、页眉或页脚。
- 短单据优先保持一页；长单据按完整产品行自动分页，并在续页重复表头。
- 中文、英文、双语三种语言均能稳定渲染。
- 现代蓝绿、经典外贸、简约商务三种现有版式继续生效。
- 全程浏览器本地处理，不上传业务数据，不要求后端。
- 保持现有人工表单、草稿、AI 模拟填单和 Excel 导出功能不变。

## 3. 不在本次范围

- 可搜索或可复制文字的矢量 PDF。
- 电子签名、数字证书、PDF 加密和防篡改。
- 服务端生成、云端存档或邮件发送。
- 新增 CRM、真实登录、支付或真实 LLM 调用。
- 新增企业 Logo 上传与图片持久化；A4 抬头先使用卖方公司名称和品牌占位区域。

## 4. 技术路线

采用 `html2canvas` 与 `jsPDF`：

1. React 根据当前 `DocumentDraft` 生成一个与页面响应式布局隔离的 A4 导出树。
2. 导出树使用固定的 210 mm × 297 mm 页面模型和固定安全边距。
3. 页面规划器先将逻辑内容拆成一个或多个 `PdfPageModel`，确保产品行、合计区和条款区不会被任意截断。
4. 每个 A4 页面独立交给 `html2canvas` 以 2 倍像素比例渲染。
5. `jsPDF` 创建 A4 纵向文件，并把每一页画布按 210 mm × 297 mm 写入对应 PDF 页。
6. 生成完成后在本地触发下载，文件名继续使用单据编号。

该路线与参考文件的视觉结果一致。PDF 页面是高分辨率图像，因此中文字体无需额外嵌入；代价是文字不可选中，文件通常约 0.5–3 MB，长单据可能更大。

## 5. 组件与职责

### 5.1 `PdfExportController`

- 接收当前草稿与导出状态回调。
- 等待 `document.fonts.ready`，避免字体尚未加载就截图。
- 创建和清理离屏导出容器。
- 逐页渲染并交给 `jsPDF` 下载。
- 防止连续点击产生多个并发任务。

### 5.2 `DocumentPdfTemplate`

- 只负责 A4 单据内容，不继承工作区网格、侧栏、滚动容器或打印 CSS。
- 使用当前单据语言和版式风格。
- 渲染公共抬头、单据信息、买卖方资料、类型专属表格、合计、条款、银行或清关资料、签章与页码。

### 5.3 `buildPdfPageModels`

- 将 `DocumentDraft` 转换为不依赖 DOM 的页面模型。
- 根据单据类型选择列定义和底部区块。
- 以完整产品行为分页单位，续页重复表头。
- 最后一页空间不足时，将合计与条款整体移到下一页。
- 空字段统一显示 `—`，数值按币种和两位小数格式化。

### 5.4 类型配置

六类单据通过配置描述差异，不复制六套导出逻辑：

| 单据 | 主要表格列 | 末尾重点区块 |
| --- | --- | --- |
| 报价单 QT | 产品与规格、数量/单位、单价、金额 | 报价有效期、贸易条款、付款方式、交期 |
| 形式发票 PI | 产品与规格、数量/单位、单价、金额 | 合计、付款方式、交期、银行资料 |
| 销售合同 SC | 产品与规格、数量/单位、单价、金额 | 合同条款、买卖方签章 |
| 商业发票 CI | 产品与规格、数量/单位、单价、金额、HS 编码 | 运输、收款与清关资料 |
| 装箱单 PL | 产品与规格、数量、箱数、净重、毛重、体积 | 总箱数、总重量、总体积、唛头 |
| 报关信息 CD | 产品与规格、数量、HS 编码、申报要素 | 原产国、运输方式、装运港、目的港、报关口岸 |

## 6. A4 视觉规范

- 页面：A4 纵向，白底，四周安全边距 12 mm。
- 抬头：品牌色横条或细线，左侧品牌区域，右侧卖方公司名称。
- 标题区：英文正式名称、中文名称或双语名称、单据编号和日期。
- 买卖方资料：两栏等宽卡片，字段标签与字段值分层显示。
- 产品表格：固定列宽、明确边框、深色表头、数字右对齐、金额突出。
- 合计：使用整行品牌色区块，币种与金额置于右侧。
- 条款：贸易术语、付款方式、交期等使用三栏或两栏信息格。
- 底部：银行、清关、备注或签章信息按单据类型出现；显示“第 N 页 / 共 M 页”。
- 字体：优先使用系统中文无衬线字体；导出前等待字体加载完成。
- 颜色：现代蓝绿为默认参考效果；经典外贸使用黑灰边框；简约商务减少色块但保留层级。

## 7. 分页规则

- 第一页保留完整抬头和买卖方资料。
- 产品表头不得单独留在页尾。
- 单个产品行不得跨页截断；内容较长时整行移到下一页。
- 续页显示简化标题、单据编号、重复表头和页码。
- 合计区必须跟随最后一行产品。
- 贸易条款与其标题保持在同一页；空间不足时整个区块移到下一页。
- 签章区不得拆分。
- 单个超长字段允许自然换行，但不得溢出边框；不截断业务文字。

## 8. 交互与错误处理

- 按钮文案在生成期间显示“正在生成 PDF…”，并暂时禁用重复点击。
- 成功后显示“PDF 已导出”。
- 失败时显示“PDF 生成失败，请检查内容后重试”，并恢复按钮状态。
- 任何异常都必须清理离屏容器和临时对象。
- 导出失败不改变草稿数据，也不影响 Excel 导出。
- 页面数据和生成结果均不发送到网络。

## 9. 数据流

`DocumentDraft` → 单据类型配置 → `PdfPageModel[]` → 离屏 A4 React 页面 → `html2canvas` 页面图像 → `jsPDF` A4 文件 → 本地下载。

屏幕右侧实时预览继续服务于编辑反馈；PDF 模板与其共享格式化函数和类型配置，但不直接截图屏幕预览，避免再次受到响应式布局影响。

## 10. 测试与验收

### 自动测试

- 六类单据分别验证标题、列定义和末尾区块映射。
- 中文、英文、双语标题与标签映射。
- 金额、重量、体积和箱数合计。
- 空字段占位和币种格式。
- 多产品分页、续页表头、合计区不拆分。
- 导出成功、依赖异常和重复点击状态。

### 构建验证

- TypeScript 编译通过。
- 现有全部测试通过。
- 生产构建通过。
- 新增依赖只包含 `html2canvas` 和 `jspdf`。

### PDF 视觉验收

为六类单据分别生成一份代表性 PDF，并使用 Poppler 渲染为 PNG 后逐页检查：

- 页面尺寸为 A4；
- 无浏览器页眉、页脚和网址；
- 无逐字换行、遮挡、溢出或断裂表格；
- 中文、英文和数字清晰；
- 页码、重复表头与分页正确；
- 简单 PI 的视觉层级达到参考文件效果。

## 11. 验收标准

本功能只有在六类代表性 PDF 全部生成成功、自动测试与生产构建通过、渲染后的所有页面无明显版式缺陷时才算完成。若某类单据存在简化，必须在交付说明中明确标注，不能以浏览器打印作为替代。
