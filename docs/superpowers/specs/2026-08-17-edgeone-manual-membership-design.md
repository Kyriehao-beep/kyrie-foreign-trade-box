# Kyrie的外贸盒子：EdgeOne 人工收费与会员系统设计

## 1. 目标与已确认决策

本阶段把现有纯前端会员演示升级为可用于早期真实收费的最小系统，同时保持低成本和低运维。

已确认的产品决策：

- 不购买或注册自定义域名，先使用平台提供的免费网址验证市场。
- 用户使用用户名和密码注册，不接短信验证码、微信授权或邮件验证。
- 每个新账号自动获得一次连续 72 小时完整试用。
- 支付页面展示经营者提供的微信和支付宝收款码。
- 支付结果由管理员人工核实，系统不对接微信支付或支付宝支付接口。
- 预留三个管理员账号，由服务端角色控制权限。
- 会员价格为月付 59 元、年付 499 元、永久买断 1299 元。
- 单据草稿、客户资料和导出数据继续留在用户浏览器，本阶段不上传服务器。
- 客户管理（CRM）仍不在本阶段范围内。

## 2. 方案比较与选择

### 2.1 采用：EdgeOne Makers 一体化

使用 EdgeOne Makers 托管 React 应用，以云函数提供账号、会话、试用、会员和管理员接口。Blob 以强一致读取模式保存账号、会话、订单、权益和审计事件，KV 只保存允许短暂延迟的限频计数和非关键配置。

优点：

- 当前免费额度足以支持早期用户验证。
- 前后端部署在同一平台，配置和排错路径最短。
- 无需购买或维护云服务器。
- 可以通过 Git 仓库持续部署。

限制：

- 平台免费额度和默认域名政策可能变化。
- Blob 可以承载早期低并发的结构化 JSON 数据，但不具备关系数据库的事务与查询能力，不适合作为长期复杂订单数据库。
- 免费默认网址在中国大陆的可访问性必须通过关闭 VPN 的真实网络验证，不能只看控制台部署成功。
- 纯客户端制单代码无法形成绝对防破解 DRM；服务端会员校验用于阻止普通绕过，不承诺抵御有开发能力的恶意复制。

### 2.2 未采用：EdgeOne 加 Supabase

Supabase 能减少认证和数据库开发，但增加第三方依赖，并存在中国大陆网络可达性风险。当前用户量不足以抵消额外复杂度。

### 2.3 备用：腾讯云 CloudBase

如果 EdgeOne 免费网址在关闭 VPN 后无法稳定访问，则使用 CloudBase 的默认测试域名作为短期备用。该默认域名可能出现安全提示、访问频率限制或续期要求，因此仍只作为过渡方案。

## 3. 账号与会话

### 3.1 注册

注册字段：

- 用户名：4–32 个字符，忽略大小写后唯一。
- 密码：至少 8 个字符。
- 联系方式：微信号或手机号，供人工核对付款和找回账号使用，不进行自动验证。

注册成功后，服务端写入用户创建时间和试用结束时间。试用结束时间固定为创建时间后 72 小时，客户端时间不能修改它。

早期版本允许公开注册。为降低批量滥用，注册与登录接口按 IP 和账号进行限频，并记录异常频次。由于不验证手机号，同一人重复注册仍可能再次获得试用；这是低成本验证阶段明确接受的风险。收入和滥用规模达到需要处理的程度后，再增加短信或微信验证。

### 3.2 登录与会话

- 密码只保存带随机盐的强哈希，不保存明文。
- 登录成功后生成随机会话令牌。
- 浏览器只接收 `HttpOnly`、`Secure`、`SameSite=Lax` Cookie。
- Blob 只保存会话令牌哈希、用户 ID、创建时间和过期时间；鉴权读取使用强一致模式。
- 普通会话有效期为 7 天；用户再次使用时可以续期。
- 退出登录、重置密码、停用账号或管理员撤销会话时，服务端删除对应会话。

### 3.3 账号找回

本阶段不建设短信和邮件自动找回。用户通过页面展示的客服联系方式申请找回，管理员核对注册联系方式和付款记录后设置一次性临时密码。用户首次使用临时密码登录后必须修改密码。

## 4. 试用与会员权益

服务端返回统一权益状态：

- `trialing`：试用中。
- `expired`：试用到期且无有效会员。
- `active_monthly`：月度会员。
- `active_yearly`：年度会员。
- `active_lifetime`：永久买断。
- `suspended`：账号停用。
- `admin`：管理员。

权益规则：

- 月付 59 元，自管理员确认到账时起增加 30 天。
- 年付 499 元，自管理员确认到账时起增加 365 天。
- 永久买断 1299 元，不设置到期时间。
- 用户提前续费时，从现有到期时间继续增加天数；已过期用户从管理员确认时间开始计算。
- 管理员拥有全部当前功能，不消耗普通会员席位。
- 所有受限页面和关键操作均以服务端权益响应为准，不信任 `localStorage`、URL 参数或前端按钮状态。

永久买断覆盖购买时已经上线的核心制单、PDF/Excel 导出、工具箱及其维护更新。未来真实 LLM、短信、第三方查询等持续产生外部调用成本的服务，可以设置合理额度或作为独立增值服务，不承诺永久无限调用。该边界必须在购买页面明确显示。

## 5. 人工收款流程

### 5.1 用户端

1. 用户选择月付、年付或永久买断。
2. 服务端生成唯一订单号并固定方案与金额。
3. 页面展示微信和支付宝收款码、订单号、金额及付款说明。
4. 用户付款时在备注中填写订单号。
5. 用户点击“我已付款”，填写付款方式、付款时间和付款人信息尾号。
6. 系统创建“待核实”付款申请，并提示人工处理，不声称已经开通。

本阶段不上传付款截图，减少文件存储、隐私处理和后台复杂度。用户可以通过客服渠道补充凭证。

### 5.2 管理员端

管理员在微信或支付宝账单中核对金额、订单号与付款人尾号，然后在后台选择：

- 确认到账并开通。
- 标记信息不匹配。
- 拒绝申请。
- 添加内部备注。

确认操作必须再次显示用户、方案、金额和权益变化。服务端以用户和订单号创建不可重复的确认事件，使用 Blob 的 `onlyIfNew` 条件写入保证同一订单只能产生一个确认事件。当前权益直接从该用户自己的确认事件前缀计算，不会再次收费或重复发放。

### 5.3 收款码风险边界

个人收款码可以用于小规模早期验证，但不具备可靠的自动到账通知、退款闭环或商业对账能力。收款码会公开展示经营者的相关身份信息。用户规模和交易频次增加后，应迁移到微信支付、支付宝商户能力或其他合规商业收款方式。

## 6. 管理后台

后台入口只对 `admin` 角色开放。前端隐藏入口不是权限控制，所有管理员接口都必须在服务端再次校验角色。

首版后台包含：

- 三个管理员账号的初始化与密码修改。
- 用户列表、用户名搜索和状态筛选。
- 查看注册时间、联系方式、试用截止时间、会员方案和到期时间。
- 查看待核实、已确认、已拒绝的付款申请。
- 一键开通月度、年度或永久会员。
- 延长指定天数、暂停账号、恢复账号。
- 生成一次性临时密码。
- 查看管理员操作日志。

不建设财务报表、自动退款、优惠券、渠道分佣、发票管理、复杂组织权限或 CRM。

## 7. 数据模型

Blob 使用带版本前缀的对象路径，避免未来迁移冲突。身份、权益、订单和管理操作读取使用强一致模式；KV 不作为这些状态的事实来源。

### 7.1 用户

- `id`
- `username_normalized`
- `username_display`
- `password_hash`
- `password_salt`
- `contact`
- `role`
- `status`
- `created_at`
- `trial_ends_at`
- `password_reset_required`

### 7.2 权益

- `user_id`
- `plan`
- `starts_at`
- `expires_at`
- `is_lifetime`
- `updated_by`
- `updated_at`
- `source_order_id`

### 7.3 付款申请

- `order_id`
- `user_id`
- `plan`
- `amount_cny`
- `payment_method`
- `payer_hint`
- `paid_at_claimed`
- `status`
- `created_at`
- `reviewed_at`
- `reviewed_by`
- `admin_note`

### 7.4 会话与日志

会话包含令牌哈希、用户、到期时间。审计日志包含管理员、动作、目标、动作前后摘要和时间，不记录明文密码或完整会话令牌。

### 7.5 按用户分区的确认事件

- `confirmed-orders-by-user/{user_id}/{order_id}.json` 是不可重复的到账确认事件。
- 管理员确认时先创建确认事件，再更新订单展示状态。
- 读取权益时只列举该用户自己的确认事件并重新计算，避免全库扫描和缓存失效问题。
- 该事件化设计用于弥补对象存储没有多记录事务的问题，同时保持低成本方案的正确性。
- 老版 `confirmed-orders` 事件在用户首次读取时迁移到按用户分区，迁移标记避免后续重复全局扫描。
- 并发创建订单、确认到账和人工发放权益都使用稳定操作键保证幂等性，中途失败可安全重试。
- 确认与拒绝共同竞争唯一的不可变订单裁决事件，避免多管理员并发操作时出现“已发权益但订单被拒绝”的矛盾。
- 新注册账号直接写入分区迁移标记，不扫描与自己无关的老数据；老用户只在完成全部索引回填后写完成标记。

## 8. 接口边界

公开接口：注册、登录、退出、读取当前账号、读取价格方案。

登录用户接口：读取权益、创建付款申请、查看自己的付款申请、修改密码。

管理员接口：列出和搜索用户、列出付款申请、确认或拒绝申请、调整权益、停用或恢复账号、生成临时密码、读取审计日志。

所有写接口执行输入校验、CSRF/同源保护、限频和统一错误响应。用户可见错误全部使用简体中文；代码、接口字段和注释使用英文。

## 9. 前端改造

- 把现有基于 `localStorage` 的 `MembershipContext` 替换为服务端会话与权益状态。
- 保留单据草稿、买卖方模板和产品数据的本地存储逻辑。
- 增加注册、登录、退出、修改密码和人工找回说明页面。
- 将“演示激活此方案”替换为真实付款申请流程。
- 删除普通用户可见的“以管理员演示”入口。
- 增加独立管理员后台路由和角色保护。
- 试用到期后保留登录、会员中心和客服入口，其余工具进入付费墙。
- 收款码缺失时不允许提交付款申请，并显示“收款方式配置中”，避免出现空白或错误二维码。

## 10. 错误处理与恢复

- EdgeOne 或网络暂时不可用时，不误判为会员到期；页面显示“暂时无法验证会员状态”，允许重试。
- 登录失败使用统一提示，避免泄露用户名是否存在。
- 付款申请重复提交时返回原订单或明确提示，不生成多个待处理订单。
- 管理员确认订单时，确认事件写入成功即代表权益已确认；不能再次创建同订单确认事件。
- 账号停用后现有会话立即失效。
- Blob 业务数据按版本导出备份；在迁移数据库前保留可恢复快照。
- 部署失败时保留当前生产版本，只有通过验收的构建才切换。

## 11. 安全与隐私

- 服务端密钥、密码哈希参数和管理员初始化信息只放 EdgeOne 环境变量，不进入 Git。
- 收款码属于公开支付入口，不把个人支付账号、账单或身份证明提交到代码仓库。
- 对注册、登录、付款申请和管理员接口设置限频。
- 管理员操作全部记录审计日志。
- 不在日志中记录密码、Cookie、完整联系方式或用户单据内容。
- 页面提供简明隐私说明，明确账号与会员信息保存在服务器，单据内容仍只在本地处理。

## 12. 部署与网址验收

1. 用户在浏览器中完成腾讯云登录。
2. 创建 EdgeOne Makers 免费项目，不购买套餐、不绑定域名。
3. 连接项目 Git 仓库或使用官方 CLI 部署。
4. 配置 Blob 存储与三个管理员初始化环境变量；收款码和客服联系方式在管理员页面上传，应用层限频使用 Blob 计数。
5. 获取平台生成的免费地址。
6. 在关闭 VPN 的中国大陆网络下测试首页、登录、函数接口、PDF 和 Excel 下载。
7. 使用不同浏览器或无痕窗口验证匿名访问。
8. 如果默认地址需要登录、返回 401、链接短时失效或访问不稳定，则不将其标记为可收费上线，改用备用托管地址或重新讨论域名方案。

## 13. 测试与验收

自动化测试覆盖：

- 用户名规范化、密码哈希与会话过期。
- 72 小时试用边界和客户端改时钟无效。
- 月付、年付、提前续费和永久买断计算。
- 同一付款订单只发放一次权益。
- 权益只读取当前用户自己的确认事件前缀，不扫描全站订单。
- 普通用户无法调用管理员接口。
- 停用、密码重置和退出使旧会话失效。
- 网络错误不被显示成试用到期。

浏览器验收覆盖：

- 注册、登录、退出和修改密码。
- 新账号获得完整 3 天试用。
- 到期账号显示正确付费墙。
- 三种方案显示 59 元、499 元和 1299 元。
- 两种收款码、订单号和“我已付款”流程。
- 管理员确认后，普通用户刷新即可获得权益。
- 三个管理员账号均能进入后台，普通用户不能进入。
- 单据草稿仍只保存在当前浏览器。
- 关闭 VPN 后的中国大陆匿名访问。
- 桌面和移动端没有明显溢出、不可点击控件或控制台错误。

## 14. 本阶段不实现

- 短信验证码、微信授权或邮箱验证。
- 微信支付、支付宝支付 API 和自动到账。
- 自动续费、自动退款和电子发票。
- 付款截图上传。
- 真实 LLM 自动填单调用。
- 客户管理（CRM）。
- 自定义域名和 ICP 备案。

## 15. 上线前需要用户提供

- 微信收款码图片。
- 支付宝收款码图片。
- 对外客服微信号或其他联系方式。
- 三个管理员的显示名称；初始用户名和临时密码由系统安全生成。

收款码和管理员凭据只在实际配置步骤中处理；在用户确认具体目标和配置位置前，不上传或写入云端。
