# Kyrie的外贸盒子 MVP 设计规格

## 1. 产品目标

「Kyrie的外贸盒子」是一款面向中国外贸业务员、SOHO 卖家和中小企业的在线制单与日常工具产品。首版以“更快完成一份可交付的外贸单据”为核心价值，通过 3 天完整试用验证付费意愿。

首版必须形成三个闭环：

1. 用户能从零创建、填写、预览并导出六类常用单据。
2. 用户能通过世界时间、汇率换算和常用工具完成日常辅助工作。
3. 用户能体验完整试用状态、到期付费墙和方案选择，但不进行真实扣款。

客户管理（CRM）不属于本次范围。

## 2. 技术与运行边界

- React 18、TypeScript、Vite、Tailwind CSS、shadcn/ui。
- 纯前端运行，业务状态保存在 React state 与 `localStorage`。
- 不建设业务后端、真实登录、真实支付或真实 LLM 调用。
- 所有导航、按钮、说明、字段名和默认示例内容使用简体中文。
- 用户选择“英文”或“双语”时，只有单据预览与导出结果使用对应语言；应用界面仍为简体中文。
- 桌面端以双栏工作台为主，移动端切换为“填写 / 预览”页签。

## 3. 信息架构

顶部导航固定包含：

- 首页
- 外贸单据中心
- 贸商工具箱
- 会员中心

### 3.1 首页

首页承担产品定位和转化：展示品牌主张、六类单据快捷入口、本地隐私承诺、AI 填单说明、工具箱预览、3 天完整试用和两类付费方案。首屏主按钮进入单据中心，次按钮查看工具箱。

### 3.2 外贸单据中心

必须包含参考站提供的全部六类单据：

- 报价单（QT）
- 形式发票（PI）
- 销售合同（SC）
- 商业发票（CI）
- 装箱单（PL）
- 报关信息／报关单（CD）

单据工作台使用左侧表单、右侧 A4 预览。顶部提供单据类型、语言和版式选择。移动端使用两个页签承载表单与预览。

共享字段包括：

- 卖方资料：企业名称、地址、联系人、电话、邮箱、税号。
- 买方资料：企业名称、地址、联系人、电话、邮箱、目的国家。
- 产品明细：品名、规格、数量、单位、单价、金额、箱数、净重、毛重、体积、HS 编码、申报要素。
- 贸易条款：贸易国家、贸易术语、付款方式、币种、交期、装运港、目的港。
- 收款与清关资料：开户行、账户名称、账号、银行地址、SWIFT、运输方式、报关口岸。

不同单据通过条件字段突出自身重点：报价有效期、合同条款、发票号、唛头、包装统计和申报要素等。金额、重量与体积由纯函数计算，用户可以新增和删除产品行。

卖方和买方资料可分别保存为复用模板。六类单据草稿使用不同存储键，避免互相覆盖。

工作台支持：

- 实时预览。
- 中文、英文、双语三种单据语言。
- 简约商务、经典外贸、现代蓝绿三种版式。
- 自动保存草稿，并显示保存状态。
- 新建空白单据。
- 清除当前草稿，执行前二次确认。
- 导出 PDF 和 Excel。
- 持续显示“本地处理、不上传云端”的隐私提示。

MVP 的 PDF 使用浏览器打印或前端 PDF 库生成，Excel 使用前端工作簿库生成。复杂字体嵌入、分页、盖章、完全一致的跨浏览器排版属于后续高保真导出范围。

### 3.3 AI 粘贴识别自动填单

AI 填单作为单据中心内的普通功能，不阻塞手工制单：

1. 用户粘贴询盘邮件、产品规格或订单备注。
2. 点击“AI 识别填单”。
3. 按钮进入加载状态并禁止重复提交。
4. 原型解析器识别预设示例中的买卖方、产品、数量、单价、国家、贸易术语和付款方式。
5. 高置信度值直接填入当前单据；低置信度或缺失字段保持空白，并标记为“请人工核对”。

解析器通过独立的异步接口暴露，未来可替换为服务端 LLM 请求。真实版本不得把模型密钥写入浏览器，也不得在没有明确提示的情况下上传用户粘贴内容。

### 3.4 贸商工具箱

世界时间面板展示约 20 个外贸城市，包括上海、迪拜、伦敦、纽约、洛杉矶、东京、新加坡、悉尼等。时间每分钟刷新，以城市当地的周一至周五 09:00–18:00 作为工作时间；其他时段标记“非工作时间”。

汇率工具支持常用币种双向换算。优先请求免费汇率 API；请求失败、超时或响应无效时使用内置静态汇率，并明确标记“当前使用离线参考汇率”及参考日期，避免把静态值伪装成实时数据。

常用快捷工具首版包含：常用贸易术语、HS 编码查询入口、集装箱尺寸参考、国际快递查询入口和外贸计算器入口。外部入口明确标注将打开第三方网站。

## 4. 试用、登录与收费设计

### 4.1 当前纯前端 MVP

首次访问时写入试用开始时间，72 小时内开放全部功能，不限制单据类型、导出、AI 模拟填单或工具箱。到期后显示付费墙，提供：

- 月度订阅。
- 年度订阅。
- 永久买断。

会员中心提供登录入口、微信支付和支付宝入口的界面占位，并明确标注“演示功能，暂未连接真实支付”。为便于验收，提供本地会员演示开关。

MVP 预留三个管理员席位，提供管理员入口和角色状态演示。管理员通过预设演示身份进入，不计入普通用户订阅，也不能借此绕过正式商业版本的服务端授权。管理员界面只展示账号与方案概况，不建设复杂运营后台。

纯前端状态可以被开发者工具修改，因此该付费墙只验证产品体验，不能用于真实商业收费。

### 4.2 商业化版本

商业化时将账号身份、支付订单和功能授权分离：

- 每个用户拥有稳定的服务端用户 ID，手机号不是会员权益的唯一凭证。
- 管理员账号采用邀请制，默认最多三个席位；管理员权限通过服务端角色字段与数据库策略校验，不能依赖前端隐藏按钮。
- 推荐微信扫码或微信网页授权作为主要登录入口；手机号验证码作为备用登录和账号找回方式。
- 手机号 OTP 必须配置短信服务商、验证码有效期、发送限流和人机验证。
- 桌面网页优先使用微信 Native 支付和支付宝电脑网站支付；移动端使用对应的网页支付能力。
- 商户后端创建唯一订单，前端只显示支付二维码或跳转地址。
- 后端必须验证支付平台异步通知签名，按订单号幂等处理，只在验签且金额、币种、商户号和订单状态全部匹配后发放权益。
- 权益保存在服务端，字段至少包括用户、方案、状态、开始时间、到期时间、永久标记和支付订单。
- 前端每次进入受限功能时读取服务端权益，不信任 `localStorage`、查询参数或前端按钮。
- 支付状态使用回调为准，主动查单仅用于补偿；记录退款、撤销和重复通知。

首个商业版本建议将月付、年付实现为“到期续费”，不立即实现自动扣款。自动续费需要额外处理签约、解约、扣款失败、重试、通知和退款规则，可在验证续费需求后再建设。

正式接入前需要准备合规主体、微信支付商户号、已认证应用标识、支付宝商户能力、线上协议、隐私政策、退款规则和客服渠道。具体准入要求以接入时的支付平台官方规则为准。

## 5. 状态与数据流

核心状态分为：

- `DocumentDraft`：当前单据类型、双方信息、产品行、贸易条款、银行和清关信息、语言、版式。
- `PartyTemplate`：可复用的卖方或买方资料。
- `TrialState`：试用开始时间和当前计算状态。
- `MembershipState`：未登录、试用中、已到期、订阅会员、买断会员。
- `AdminState`：普通用户或受邀请管理员，以及最多三个管理员席位的演示状态。
- `RateState`：汇率来源、更新时间、币种和数值。

表单修改先更新 React state，再通过防抖写入 `localStorage`。预览只消费标准化后的 `DocumentDraft`，不直接读取表单 DOM。导出功能消费同一标准化数据，确保预览和导出内容一致。

## 6. 错误处理

- `localStorage` 不可用时继续允许制单，并提示“当前浏览器无法保存草稿”。
- 汇率请求失败时切换静态表并显示来源状态。
- AI 模拟解析失败时不覆盖当前表单，保留粘贴原文并允许重试。
- PDF 或 Excel 生成失败时保留草稿并显示可操作的失败提示。
- 清除草稿、新建单据和覆盖已填写内容必须确认。
- 所有可恢复错误使用页面内提示，不使用只有开发者能理解的错误文本。

## 7. 视觉规范

整体采用克制的绿色与蓝色体系，强调可信、清晰和专业。使用 shadcn/ui 的按钮、卡片、输入框、选择器、页签、对话框、表格、徽章和提示组件。避免营销页面的高饱和渐变和过度动画。

桌面端最大内容宽度保持舒适阅读，表单和预览均可独立滚动；移动端按钮保持足够触控尺寸，表格转换为可横向滚动或卡片式产品行。

## 8. 测试与验收

自动化测试覆盖：

- 产品金额、总金额、重量和体积计算。
- 六类草稿隔离、模板保存、清空和存储异常。
- 3 天试用边界、到期状态和本地会员演示状态。
- AI 示例解析、低置信度标记和失败不覆盖。
- 汇率接口成功、失败和静态回退。
- 世界时间的工作时间判定。

浏览器验收覆盖：

- 四个顶部导航入口。
- 六种单据切换、输入和独立草稿恢复。
- 中英双语和三种版式切换。
- 产品行增删与汇总计算。
- AI 模拟填单和人工核对提示。
- PDF、Excel 文件成功生成并可打开。
- 试用中、已到期和已激活三个状态。
- 三个管理员席位、管理员入口和普通用户权限边界。
- 桌面、平板和手机布局。
- 页面无明显控制台错误、溢出和不可点击控件。

## 9. 明确简化项

- AI 填单使用可替换的模拟解析器，不调用真实 LLM。
- 会员、登录和支付只实现交互原型，不具备真实安全授权能力。
- PDF 与 Excel 满足 MVP 可导出，不承诺复杂模板的印刷级一致性。
- 汇率在离线时为带日期的参考数据，不是实时行情。
- 常用工具快捷项以核心计算器和可信外部入口为主，不复制所有第三方服务。
