# 六类外贸单据 PDF 与 Excel 高保真导出设计

日期：2026-08-16  
状态：用户已确认并要求直接执行  
适用产品：Kyrie的外贸盒子  
替代范围：本设计替代 `2026-08-16-a4-pdf-export-design.md` 的 PDF 单项范围，并将 Excel 纳入同一导出体系

## 1. 背景与根因

当前 PDF 直接打印响应式网页，导致浏览器页眉、网址、错误分页、中文逐字换行和表格挤压。当前 Excel 则把数据拆成“单据资料”和“产品明细”两个无样式数据表，缺少正式单据的视觉层级、打印设置和客户交付观感。

参考 PDF 和参考 Excel 的共同特征是：它们都先建立固定的正式单据版式，再把业务数据写入标题、买卖方资料、产品表格、合计和条款等明确区域。问题的底层解法不是继续修补浏览器打印或给原始数据表加少量颜色，而是建立一个由单据配置驱动、分别输出 A4 PDF 与正式 Excel 的导出模型。

## 2. 已确认的产品目标

- 一次性修正报价单 QT、形式发票 PI、销售合同 SC、商业发票 CI、装箱单 PL、报关信息 CD 六类单据。
- PDF 和 Excel 均达到可直接发送客户、归档和打印的专业程度。
- Excel 每次只生成一张正式单据工作表，不保留可见或隐藏的原始数据表。
- PDF 与 Excel 共用字段语义、类型配置、语言标签、格式化规则和合计逻辑，避免两种文件内容不一致。
- 中文、英文、双语三种文档语言继续生效。
- 现代蓝绿、经典外贸、简约商务三种版式继续生效。
- 全程在浏览器本地生成，不上传业务数据，不增加后端运行成本。
- 文件名继续使用当前单据编号；编号为空时使用中文兜底名称。

## 3. 不在本次范围

- 企业 Logo 上传、图片裁剪和 Logo 持久化。
- 可搜索文字的矢量 PDF、PDF 字体嵌入、数字签名、加密或防篡改。
- 服务端文件生成、云端归档、邮件发送或多人协作编辑。
- Excel 宏、VBA、数据透视表和外部数据连接。
- 真实登录、收费、支付、CRM 或真实 LLM 调用。
- 完全复制参考站的私有代码或模板文件；仅对齐其可观察的业务结构和专业视觉效果。

## 4. 技术方案选择

### 4.1 PDF

采用 `html2canvas@1.4.1` 与 `jspdf@4.2.1`：

1. React 根据当前 `DocumentDraft` 构建与响应式工作区隔离的 A4 导出树。
2. 页面规划器将产品行和末尾区块拆成稳定的 `PdfPageModel[]`。
3. 每个固定 210 mm × 297 mm 页面以 2 倍像素比例渲染为画布。
4. `jsPDF` 按 A4 纵向逐页写入并触发本地下载。

PDF 以高分辨率页面图像保证中文和版式稳定。文字不可选中是本次明确接受的简化。

### 4.2 Excel

采用 `exceljs@4.4.0` 的浏览器构建并动态导入：

1. `DocumentDraft` 先转换为与库无关的 `ExcelDocumentModel`。
2. Excel 渲染器创建一个工作簿和一个正式单据工作表。
3. 渲染器按模型设置合并单元格、值、公式、字体、填充、边框、列宽、行高和对齐。
4. 设置与参考工作簿一致的 A4 横向、单页宽度、自适应多页高度、页边距、打印区域和续页表头。
5. 通过浏览器 Blob 下载 `.xlsx`，不保留额外数据工作表。

不继续依赖现有 `xlsx@0.18.5` 生成最终文件，因为当前实现只输出二维数据数组，无法可靠达到参考文件所需的样式、分页和打印控制。完成迁移后移除该直接依赖，避免同时维护两套 Excel 引擎。

ExcelJS 4.4.0 的默认依赖树在 2026-08-16 仍包含已披露问题的 `uuid@8.x`。项目必须通过 pnpm overrides 将 ExcelJS 使用的传递依赖固定为 `uuid@11.1.1` 和 `tmp@0.2.7`，并在安装后执行生产依赖审计。`tmp@0.2.7` 取代设计初稿中的 `0.2.6`，因为实时审计已将 `0.2.6` 列为高危。若覆盖版本导致 ExcelJS 浏览器构建、工作簿写入或生产审计失败，则停止发布，不以忽略审计告警作为完成条件。

## 5. 共享导出模型

### 5.1 `DocumentExportDefinition`

六类单据通过配置描述差异，不复制六套完整逻辑。配置包含：

- 中文标题、英文标题和工作表名称；
- 产品列、列宽、数据类型和对齐方式；
- 末尾区块类型；
- 金额、数量、重量、体积和箱数的显示规则；
- PDF 行高估算和 Excel 打印表头范围所需的元数据。

### 5.2 共享格式化

- 空文本统一显示 `--`。
- 金额保留两位小数并显示当前币种代码。
- 数量和箱数保留有效小数，不强制显示无意义的小数位。
- 净重、毛重显示 `KG`，体积显示 `CBM`。
- 日期使用稳定的 `yyyy-mm-dd` 数据值；文件内标签随文档语言变化。
- 双语标题采用“英文 / 中文”，双语字段采用同一单元格双语标签。

### 5.3 合计逻辑

- PDF 使用共享的纯函数计算并显示结果。
- Excel 产品金额单元格使用“数量 × 单价”公式。
- Excel 总金额和总箱数使用 `SUM` 公式；总净重、总毛重和总体积按现有数据语义使用“数量 × 单件数值”的逐行公式后汇总。
- Excel 打开后修改数量、单价或包装数据，相关合计自动更新。
- 公式只引用当前正式单据页中的有界区域，不使用整列引用或隐藏数据页。

## 6. 六类单据内容定义

| 单据 | 产品表核心列 | 末尾专属内容 |
| --- | --- | --- |
| 报价单 QT | 序号、品名、规格、数量/单位、单价、金额 | 报价有效期、贸易条款、付款方式、交期、备注 |
| 形式发票 PI | 品名、规格、数量/单位、单价、金额 | 贸易条款、付款方式、装运信息、银行收款资料 |
| 销售合同 SC | 品名、规格、数量/单位、单价、金额 | 贸易条款、付款方式、交期、备注、买卖双方签章区 |
| 商业发票 CI | 品名、规格、数量/单位、单价、金额、HS 编码 | 发票总额、贸易国、运输与清关、收款资料 |
| 装箱单 PL | 品名、规格、数量、箱数、单件净重、单件毛重、单件体积 | 总数量、总箱数、总净重、总毛重、总体积、唛头 |
| 报关信息 CD | 品名、规格、数量、HS 编码、申报要素 | 贸易国、成交方式、运输方式、报关口岸和备注 |

只显示当前单据有业务意义的列和末尾区块。字段严格映射现有 `DocumentDraft`：贸易国使用 `trade.country`，成交方式使用 `trade.incoterm`，运输方式和报关口岸使用 `settlement` 对应字段，合同补充条款和报关备注使用 `notes`。本次不虚构或新增当前表单未采集的商品编码、监管方式、境内货源地和独立质量条款。

## 7. PDF 版式与分页

- 页面固定为 A4 纵向，白底，四周安全边距 12 mm。
- 第一页包含完整品牌抬头、单据标题、编号、日期和买卖方资料。
- 产品表使用固定列宽、深色表头、数字右对齐；续页重复简化标题和产品表头。
- 单个产品行不得跨页截断，产品表头不得单独停留在页尾。
- 合计区跟随最后一行产品；末尾条款或签章空间不足时整体移动到下一页。
- 每页显示“第 N 页 / 共 M 页”。
- 导出文件不包含浏览器日期、网址、页眉或页脚。

## 8. Excel 工作表版式

每次导出仅创建一张正式工作表，按以下顺序排列：

1. 深绿色品牌页眉，显示卖方公司名称；为空时显示“Kyrie的外贸盒子”。
2. 单据标题、单据编号和开具日期。
3. 左右双栏的卖方资料与买方资料。
4. 类型专属产品表格。
5. 浅绿色合计区，突出显示币种与总金额或包装合计。
6. 贸易条款、银行信息、清关资料、签章或报关备注等类型专属区块。

视觉规则：

- 默认字体为“Microsoft YaHei”，兼容时由 Excel 使用系统回退字体。
- 深绿色表头搭配白字，浅绿色区块用于资料标题和合计。
- 文本左对齐，标题居中，数字和金额右对齐。
- 使用有目的的细边框划分信息区，不给空白区域添加装饰边框。
- 合并单元格只用于标题、资料卡、标签和值区域，不用于公式计算区域。
- 产品行根据内容启用换行并设置合理行高；不使用全表自动适应导致不可控宽度。
- 隐藏默认网格线，保持清晰的正式单据观感。

打印规则：

- A4 横向，适应为一页宽、多页高；该方向按用户提供的 `QT-202608-0295.xlsx` 参考文件确认。
- 使用窄而安全的打印页边距，水平居中。
- 打印区域仅覆盖实际单据内容。
- 多页产品表重复产品表头。
- 合计和末尾条款只在产品数据结束后出现，不重复打印。

## 9. 三种版式

- 现代蓝绿：深青绿色品牌条、浅绿色信息卡和明确的金额重点，作为默认并最接近参考文件。
- 经典外贸：减少大面积填色，使用深灰文字、较明显边框和传统表格层级。
- 简约商务：保留标题与表头重点，减少边框和色块，增加留白。

三种版式只改变视觉标记，不改变字段、公式、分页规则或工作表数量。

## 10. 数据流与文件边界

PDF：

`DocumentDraft` → `DocumentExportDefinition` → `PdfPageModel[]` → 离屏 A4 React 页面 → `html2canvas` → `jsPDF` → 本地 PDF。

Excel：

`DocumentDraft` → `DocumentExportDefinition` → `ExcelDocumentModel` → ExcelJS 单工作表渲染 → `writeBuffer()` → Blob → 本地 XLSX。

屏幕实时预览继续服务编辑反馈。PDF 和 Excel 都不直接截取或导出响应式屏幕预览，也不向网络发送单据数据。

## 11. 交互与错误处理

- PDF 生成时按钮显示“正在生成 PDF…”，并禁用 PDF 重复点击。
- Excel 生成时按钮显示“正在生成 Excel…”，并禁用 Excel 重复点击。
- 成功分别显示“PDF 已导出”和“Excel 已导出”。
- 失败分别显示明确的中文重试提示，并恢复按钮状态。
- PDF 或 Excel 导出失败不改变当前草稿，也不阻断另一种格式的导出。
- 动态依赖加载、字体等待、画布渲染或工作簿写入异常都在统一边界捕获。
- 临时 DOM、Blob URL 和下载节点必须在成功或失败后清理。

## 12. 测试设计

### 12.1 共享模型测试

- 六类标题、工作表名称、列定义和末尾区块映射。
- 中文、英文、双语标签。
- 金额、数量、重量、体积、空值和币种格式。
- 六类单据只出现各自需要的列。

### 12.2 PDF 测试

- 短单据单页、长单据续页、完整产品行不拆分。
- 续页重复标题和表头，只有最后一页显示合计与末尾区块。
- 六类 React 页面都渲染对应专属内容。
- 多页捕获顺序、文件名、依赖异常和空导出树。

### 12.3 Excel 测试

- 每个工作簿恰好一个工作表，名称与单据类型一致。
- 合并区域、关键行列、样式角色、列宽、行高和隐藏网格线正确。
- 产品金额和合计使用正确的 Excel 公式和有界引用。
- A4 横向、适应一页宽、打印区域和重复表头正确。
- 六类单据的专属列与末尾内容正确。
- 中文、英文、双语和三种版式至少覆盖代表性组合。
- 生成的 `.xlsx` 可被重新导入，关键值与公式无错误。

### 12.4 视觉验收

- 为六类单据分别生成一份 PDF 和一份 Excel，共十二份 QA 文件。
- PDF 使用 Poppler 渲染全部页面并检查 A4、分页、中文和表格完整性。
- Excel 渲染每个工作表并检查标题、买卖方、表头、合计、条款和打印层级。
- QT Excel 的信息层级向参考 `QT-202608-0295.xlsx` 对齐。
- PI PDF 的信息层级向参考 `PI-202608-6369.pdf` 对齐。

### 12.5 构建与依赖验证

- 精确锁定 `html2canvas@1.4.1`、`jspdf@4.2.1` 和 `exceljs@4.4.0`。
- 移除现有 `xlsx@0.18.5` 直接依赖。
- 锁定 ExcelJS 的 `uuid@11.1.1` 与 `tmp@0.2.7` 传递依赖覆盖。
- 生产依赖审计不得包含已知高危漏洞；ExcelJS 浏览器构建与写入测试必须通过。

## 13. 验收标准

- 六类 PDF 均能打开，尺寸为 A4，无浏览器页眉、网址、压缩列或中文逐字换行。
- 六类 Excel 均只有一个正式工作表，视觉上可直接发送客户，且产品金额与合计公式有效。
- PDF 与 Excel 的标题、产品数据、合计和类型专属信息一致。
- 所有自动测试、TypeScript 编译和生产构建通过。
- 十二份代表性导出文件完成视觉检查，无文字裁切、重叠、严重空白或分页断裂。
- 保持本地处理，不新增后端和付费服务。
- 任何保留的简化必须在最终交付说明中明确标注。
