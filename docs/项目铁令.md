# 项目铁令

## 1. Skill 优先调用铁令

**每次执行任务前，必须先去 skill 库（`~/.workbuddy/skills/` 及本项目 `.user_skills/`）检索是否有可调用的 skill。有可调用的就必须调用，不得跳过。**

### 执行流程

1. 任务开始前，用关键词在 skill 库中检索（中英文均可）
2. 找到匹配的 skill 后，读取其 `SKILL.md`，严格遵循其工作流/检查清单/方法论执行
3. 无匹配 skill 时，直接执行并说明原因

### 常见场景与对应 skill

| 场景 | 必调 skill |
|---|---|
| 全栈功能开发 / 前后端集成 | `fullstack-dev` |
| UI 设计 / 页面重构 / 视觉优化 | `ui-ux-pro-max` |
| GitHub Pages 部署 + E2E 验证 | `ghpages-spa-deploy-e2e` |
| 定价策略 / 价格调整 | `pricing analyst` |
| 代码审查 / PR 审查 | `code-review` |
| Bug 排查 / 故障诊断 | `diagnosing-bugs` / `systematic-debugging` |
| 测试驱动开发 | `tdd` / `superpowers-test-driven-development` |
| 压缩上下文 / 精简输出 | `caveman` |
| 跨境电商 / 外贸策略 | `agency-cross-border-ecommerce` |
| 供应链 / 物流 / 单证流程 | `agency-supply-chain-strategist` |

### 本项目可用 skill 位置

- WorkBuddy skill 库：`~/.workbuddy/skills/`（85 个，已同步到本项目 `.user_skills/`）
- 豆包内置 skill：`~/.skills/`（100+ 个）

## 2. 决策前告知弊端铁令

**任何需求执行前，必须先与用户确认范围，且产品的弊端/缺点必须在执行前告知用户。**

- 不得静默执行有副作用的决策
- 涉及架构变更、付费、第三方依赖、托管迁移等，必须先列利弊再动手
- 用户确认后再执行

---

## 3. 文档落盘铁令

执行任务时，相关文档必须保存到项目 `docs/` 目录。
