## 一、报价助手（合并 + 修错 + 公式单一来源）

### 1.1 合并两个重复的计算器

原先 `/quote` 页面同时挂着两个互不兼容的计算器：

- `QuoteAssistant.tsx`：整单口径的费用（国内杂费 / 国内运费 / 国际运费都是整单），但把客户目标价当成单件用。
- `QuoteCalculator.tsx`：FOB/CIF 单件口径，字段命名完全不同（含 `reverseCeiling()` 反算最高采购价）。

**处理**：删除 `QuoteCalculator.tsx`，只保留重写后的 `QuoteAssistant.tsx`。
删除前已确认全仓只有 `QuotePage.tsx` 引用它，`compute`/`reverseCeiling` 未对外导出，无隐藏调用方。

### 1.2 旧的 -7919.4% Bug 根因

旧代码在 `QuoteAssistant.tsx` 里这样算：

```
targetRevenue = targetUSD × fx      // 单件（美元→人民币）
targetProfit  = targetRevenue - totalCost   // totalCost 是整单！
```

`targetUSD` 是**每件**价，`totalCost` 是**整单**成本，两者直接相减，于是利润率炸成 -7919.4%，
目标报价被算成 $1,994.84。同时还有两个次生问题：

- 整单费用（`domesticMisc` / `domesticFreight` / `intlFreight`）没有按数量摊到单件；
- 退税率直接乘在含税采购价上，没有先剥离增值税。

### 1.3 修复方案：单一公式来源 + 命名强制口径

新增 `src/domain/quote.ts`，所有报价计算只在这一个文件里发生，UI 不允许自己算。
用命名从结构上防止口径混淆：

- 带 `unit` / `Unit` 前缀 → **每件**
- 带 `order` / `Order` 前缀 → **整单**（= 单件值 × 数量）

### 1.4 公式说明

```
① 单件实际采购成本
   netPurchase      = 单件含税采购价 ÷ (1 + 增值税率)
   rebatePerUnit    = netPurchase × 出口退税率        ← 退税按不含税进价退
   actualPurchase   = 单件含税采购价 − rebatePerUnit

② 单件到岸成本
   fobCostPerUnit   = actualPurchase + 单件包装 + 单件国内操作费
   CIF 时：
     cifValuePerUnit = (fobCostPerUnit + 单件国际运费) ÷ (1 − 保险费率)
     insurancePerUnit = cifValuePerUnit × 保险费率     ← 保费按 CIF 金额计
   baseCostPerUnit  = fobCostPerUnit + 单件国际运费 + insurancePerUnit

③ 整单费用摊薄（数量越大单件负担越低）
   orderFixedPerUnit = (国内杂费 + 国内运费) ÷ 数量

④ 单件人民币成本
   unitCostCNY = baseCostPerUnit + orderFixedPerUnit

⑤ 按报价额收取的费用
   feeRate = (平台扣点 + 收款手续费 + 佣金) ÷ 100

⑥ 保本价（利润为 0）
   breakEvenCNY = unitCostCNY ÷ (1 − feeRate)
   breakEvenUSD = breakEvenCNY ÷ 汇率

⑦ 建议报价（达到目标利润率，利润率按报价额计）
   suggestedCNY = unitCostCNY ÷ (1 − feeRate − 目标利润率)
   suggestedUSD = suggestedCNY ÷ 汇率

⑧ 单件利润 / 利润率
   unitFeeCNY     = suggestedCNY × feeRate
   unitProfitCNY  = suggestedCNY − unitCostCNY − unitFeeCNY
   unitProfitRate = unitProfitCNY ÷ suggestedCNY

⑨ 整单值（严格 = 单件 × 数量）
   orderCostCNY   = unitCostCNY   × 数量
   orderAmountCNY = suggestedCNY  × 数量
   orderAmountUSD = suggestedUSD  × 数量
   orderProfitCNY = unitProfitCNY × 数量

⑩ 客户目标价分析（全部用单件口径，这是 bug 的修复点）
   targetUnitPriceCNY = 客户目标价 × 汇率
   targetUnitProfitCNY = targetUnitPriceCNY − unitCostCNY − targetUnitPriceCNY × feeRate
   targetGapUSD        = 客户目标价 − 保本价
   targetBelowBreakEven = 客户目标价 > 0 且 客户目标价 < 保本价
   targetShortfallOrderCNY = 客户目标价低于保本价时的整单亏损额

⑪ 汇率压力测试
   fxDropped          = 汇率 × (1 − 汇率风险预留%)
   fxDropUnitProfitCNY = suggestedUSD × fxDropped − unitCostCNY
                          − suggestedUSD × fxDropped × feeRate
```

### 1.5 防御性处理

| 输入情况 | 处理 |
|---|---|
| 数量 ≤ 0 或 NaN | 回退为 1 |
| 汇率 ≤ 0 或 NaN | 回退为 1 |
| 负数金额 | 取 0 |
| 百分比 < 0 或 ≥ 100 | 夹到 [0, 99.999]，保证分母为正 |
| NaN / Infinity | `safeNum()` 归零，`fin()` 兜底，绝不上屏 |
| 扣点合计 ≥ 100% | `invalid.feeRate = true`，保本价/建议报价置 0 并提示 |
| 扣点 + 利润率 ≥ 100% | `invalid.margin = true` |
| 保险费率 ≥ 100%（CIF） | `invalid.insurance = true`，保费置 0 |

### 1.6 三步结构

1. **快速报价**：产品名称、数量、单件采购成本（含税）、单件包装成本、目标利润率、客户目标价、汇率、贸易条款（FOB/CIF）。
2. **高级费用**：增值税率、出口退税率、单件国内操作费、单件国际运费、国内杂费（整单）、国内运费（整单）、保险费率、汇率风险预留、平台扣点、收款手续费、佣金。
3. **报价结果**：六项必填指标 + 价格锚点 + 费用明细 + 报价话术 + 生成 PI。

每个数字旁都带「每件」或「整单」标签；输入框也带口径徽标。

### 1.7 六项必填指标

单件人民币成本 / 单件美元报价 / 整单人民币成本 / 整单美元金额 / 单件利润 / 整单利润。

### 1.8 产品图片

图片**仅**用于生成的 PI 与报价展示，不参与任何计算，页面上明确写了「不会做任何图像识别」。

## 四、顺带修复的真实 Bug：汇率接口已迁移（影响报价准确性）

`src/services/rates.ts` 原先用 `https://api.frankfurter.app/latest`，该域名现已 301 到
`api.frankfurter.dev/v1/latest`。**301 响应本身不带 CORS 头**，浏览器会在跟随跳转前就被拦截，
于是应用**永远走离线兜底**，并在控制台报错。

更严重的是离线兜底值是 `CNY = 7.18`，而真实汇率是 `6.7209`——**偏差约 6.4%**，
会直接把报价算高。已修正：

- 端点改为 `https://api.frankfurter.dev/v1/latest`（实测返回 200 且带 `access-control-allow-origin: *`）
- 离线兜底更新为 2026-08-28 的真实快照（CNY 6.7209，其余币种同步刷新）
- `DEFAULT_QUOTE_INPUT.fxRate` 同步改为 6.7209，并新增测试锁定两者一致，防止再次漂移
